CODEBREAKERS
El misterio del código oculto

La bóveda digital de una empresa ficticia está protegida por un programa cuyo código fuente se ha perdido. Tienes el ejecutable y una misión: encontrar la clave y explicar cómo la descubriste. La contraseña correcta no está escrita en texto plano: está protegida con cifrado AES-256.

🧩 Ingeniería inversa🔐 AES-256💻 Windows + Ghidra🔍 Reto educativo⏱ 15–25 minutos🔒 Sin sistemas reales

🎯 ¿Qué vas a lograr?

1 · Inspeccionar

Abrir un archivo binario Linux usando Ghidra en Windows.

2 · Investigar

Encontrar textos y referencias dentro del programa.

3 · Explicar

Interpretar una comparación de cadenas en código descompilado.

4 · Validar

Probar la clave y compartir la evidencia con el monitor.

Regla del laboratorio: analiza exclusivamente el archivo entregado por tu monitor. No uses cuentas, contraseñas, redes ni aplicaciones de terceros. Ghidra no es Hydra: aquí se utiliza Ghidra, no herramientas de pruebas de contraseñas.

Ruta recomendada: Windows 10/11 (64 bits). Puedes analizar el binario Linux directamente desde Ghidra. No necesitas ejecutar el ELF para resolver la parte de investigación.

Preparación en Windows

  1. Descarga la distribución ZIP precompilada de Ghidra, no el ZIP «Source code».
  2. Descomprime Ghidra en una carpeta local.
  3. Abre el archivo ghidraRun.bat que está en esa carpeta.
  4. Extrae el ZIP del reto en Descargas\CODEBREAKERS u otra carpeta fácil de localizar.
  5. No renombres el ejecutable agregándole .exe: Windows no lo ejecutará así.

Preparación en Linux o WSL

Ghidra funciona también en Linux. Puedes analizar el archivo en Ghidra y ejecutar el ELF en una terminal x86-64.

chmod +x reto_codebreakers_linux_x64
./reto_codebreakers_linux_x64

En WSL, primero navega a la carpeta montada, por ejemplo cd /mnt/c/Users/TU_USUARIO/Downloads/CODEBREAKERS/participantes. Ajusta la ruta a tu PC.

Paso 1 · 3 minutos
1

Crear el proyecto e importar el programa

  1. En la ventana principal de Ghidra, haz clic en File → New Project.
  2. Elige Non-Shared Project, define una carpeta y usa el nombre ECI_CODEBREAKERS.
  3. Haz clic en File → Import File... y selecciona reto_codebreakers_linux_x64.
  4. Comprueba que Ghidra lo identifica como ejecutable de tipo ELF para arquitectura x86-64.
  5. Haz doble clic en el programa importado. Cuando aparezca la ventana de análisis, selecciona Yes → Analyze.
✅ Resultado esperado: se abre la ventana de análisis de Ghidra (CodeBrowser), con paneles como Listing y Decompiler.
Paso 2 · 3 minutos
2

Buscar pistas dentro del ejecutable

  1. Con el programa abierto, usa Search → for Strings....
  2. Presiona Search. Revisa las cadenas de texto detectadas.
  3. Busca mensajes sobre acceso concedido o denegado, solicitudes de clave y valores que parezcan una clave AES-256 (32 bytes), un vector de inicialización (IV) o un texto cifrado. La contraseña no está en texto plano.
  4. Haz doble clic en una cadena interesante para verla en la ventana Listing.
Pregunta para pensar: si el programa está compilado, ¿por qué algunos mensajes todavía pueden leerse como texto normal?
Paso 3 · 4 minutos
3

Identificar cómo se comprueba la clave

  1. En Listing, selecciona una cadena que parezca estar relacionada con la validación.
  2. Haz clic derecho y busca References → Show References To o una opción equivalente, según tu versión.
  3. Abre una referencia que conduzca a código.
  4. Revisa el panel Decompiler (si está oculto: Window → Decompiler).
  5. Localiza una llamada parecida a strcmp(entrada, ...) y observa qué ocurre cuando su resultado es 0.
// Este es un EJEMPLO conceptual, no la solución real:
texto_descifrado = aes256_descifrar(TEXTO_CIFRADO, CLAVE_AES, IV);
if (strcmp(texto_usuario, texto_descifrado) == 0) {
    mostrar("ACCESO CONCEDIDO");
} else {
    mostrar("ACCESO DENEGADO");
}
Explicación sencilla: el programa no guarda la contraseña en texto plano. Primero descifra un texto cifrado con AES-256 (usando una clave de 32 bytes y un vector de inicialización) y luego usa strcmp, que compara dos textos y devuelve 0 cuando son iguales. Debes explicar cómo se recupera la contraseña y cómo esa comparación controla la respuesta del programa.
Paso 4 · 2 minutos
4

Validar tu hipótesis

Si tu equipo es solo Windows y no tiene WSL, puedes usar este verificador auxiliar sin conexión. Este formulario cifra tu clave con el mismo AES-256 del reto y la compara con el texto cifrado; no ejecuta el archivo ELF.

Aún no has enviado una clave.
Pista 1 · ¿Por dónde comenzar?

Busca cadenas de texto en Search → for Strings. Verás la clave AES-256 de 32 bytes, el vector de inicialización (IV) y un texto cifrado, pero no la contraseña en texto plano.

Pista 2 · ¿Qué relación tiene con AES-256 y strcmp?

El programa descifra el texto con AES-256 y luego compara la entrada del usuario mediante strcmp. Para resolverlo, reproduce el descifrado con la clave y el IV que encontraste.

Pista 3 · ¿Cómo confirmo que encontré el lugar correcto?

Explica qué ruta del if/else imprime «ACCESO CONCEDIDO» y verifica tu hipótesis aquí o con el programa en Linux/WSL.

Si el monitor tiene Linux/WSL

chmod +x reto_codebreakers_linux_x64
./reto_codebreakers_linux_x64

El programa pedirá la clave en una terminal. Esta comprobación es la validación directa del binario.

Reflexión final: ¿por qué no es seguro guardar una contraseña fija y reutilizable dentro de un programa distribuido a los usuarios? Aunque ahora esté cifrada con AES-256, la clave de descifrado también viaja dentro del ejecutable, así que el cifrado solo dificulta (no elimina) el problema.
